Object-Detection Cheat-Sheet

The metrics, the model, and the training loop — explained against Snug's own YOLO26n furniture detector. The running example is nightstand, the weakest class.

1 · What the model outputs

Per image, the detector emits a list of predictions. Each row = a box + a label + a confidence:

[x1, y1, x2, y2, score, classIndex] └── where ──┘ 0.83 10 = nightstand

Everything below is just bookkeeping on how often these rows are right.

2 · Is a box correct? → IoU

Intersection over Union

IoU = area of overlap ÷ area of union (0 = miss … 1 = perfect)

A prediction "hits" a real box if IoU ≥ 0.5. The 50 in AP50 is that 0.5 bar.

Every prediction then falls into one bucket:

TP — said nightstand, was one ✓
FP — said nightstand, wasn't (hallucination)
FN — was a nightstand, stayed silent (miss)
TN — not meaningful in detection

3 · Precision vs Recall — the core pair

Precision

TP ÷ (TP + FP)

"Of what I flagged, how much was real?" Punishes hallucinations.

Nightstand: 0.768 — fine.

Recall

TP ÷ (TP + FN)

"Of what existed, how much did I catch?" Punishes misses.

Nightstand: 0.382 — caught <4 of 10.

The whole bug in one line: high precision + low recall = a shy, confused class. The model isn't lying about nightstands — it stays silent, hedging between nightstand / side_table / dresser. F1 = 2·P·R/(P+R) is the single score that's only high when both are.

4 · The confidence-threshold knob

P and R aren't fixed — they slide as you move the score cutoff:

threshold LOW → fires on everything → recall ↑ precision ↓ threshold HIGH → fires only when sure → precision ↑ recall ↓ ← Snug app: 0.70

Snug gates at minimumConfidence = 0.70 — far right of the curve, where a shy class goes nearly silent. That's why lowering the floor for nightstand recovers recall today.

5 · AP50 · mAP — scoring across all thresholds

Sweep the threshold high→low, trace precision vs recall = the PR curve. Area under it = AP (one class).

MetricMeaning
AP50Area under PR curve, using IoU ≥ 0.50 as the hit bar
AP50-95Average AP over IoU 0.50→0.95 — also demands tight boxes (always lower)
mAPmean AP across all 11 classes (the "m")

7 · The model — YOLO26n

YOLO"You Only Look Once" — detects in a single forward pass → real-time on-device. n = nano~5 MB, smallest size (n<s<m<l<x), chosen for the offline live AR pan.

image 640×640 │ [ BACKBONE ] conv layers extract features (edges → parts → "cushion-like") │ [ NECK ] fuses scales (FPN/PAN) so big sofa AND small nightstand both seen │ [ HEAD ] outputs box coords + class scores per location

anchor-free (predicts geometry directly) · end2end / NMS-free export → clean (1,300,6) tensor, no in-app NMS · 640px input (small/far nightstands lose detail here).

8 · How it trains

1
Forward — run a batch of images → predictions
2
Loss — compare to labels → one error number = box_loss + cls_loss + dfl_loss. (cls_loss = where nightstand↔side_table confusion lives)
3
Backward — backprop computes the gradient (which way each weight should move)
4
Step — optimizer nudges every weight by learning-rate × gradient

Repeat over batches × epochs (full passes). Snug ran 10 — low; rare classes still improving when it stopped.

Transfer learning: you start from COCO-pretrained weights and adapt the head to 11 furniture classes — that's why ~28k images is enough. The backbone already knows "edges, legs, surfaces."

10 · Training → your iPhone

best.pt ──export──► YOLO26nFurniture.mlpackage ──Vision/CoreML──► Neural Engine

NMS (Non-Max Suppression): a detector fires many overlapping boxes per object; NMS keeps the top-score one, drops the rest. Snug bakes it into the model (end2end) → in-app code just decodes the tensor.

Note: the app's runtime IoU "consensus" (≥3 frames) is a different use of IoU — across frames, to confirm a piece is real, not within one frame.

11 · Think like an MLE

  1. Decompose every aggregate. mAP50 0.743 looked fine; per-class exposed nightstand 0.554.
  2. Low-precision ≠ low-recall. Different diseases, different cures. Nightstand is a recall disease.
  3. Volume vs confusion. Desk beats nightstand with less data → confusion, not volume. This picks the fix.
  4. Constraints pick the model. Offline + real-time + on-device ⇒ nano + CoreML, not a giant open-vocab net.
  5. Taxonomy is a design lever. Splitting tables 5 ways created the confusion. Merging is the most underrated fix.
